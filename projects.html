Project 01 / Form Study

井关集团小马力拖拉机外观迭代设计

用户感知视角下的小马力拖拉机外观评价与设计应用

感性意象评价形态特征编码因子分析参数转译外观迭代

本项目分析圆润与硬朗、流畅与粗犷等外观意象与构件轮廓的关联，并结合井关品牌特征，开展小马力拖拉机外观迭代设计。

Research Process / 研究过程
  1. 对象界定选取小马力拖拉机样本，用语义词对描述外观意象。
  2. 证据获取采集外观评价，分析感知维度与构件轮廓的关联。
  3. 设计应用将关联分析用于构件选择，并调整比例、曲面与色彩。
  4. 方案评价比较初步方案，完成修改后再进行语义评价。
Summary / 项目摘要

选取8款车型作为评价样本，结合构件轮廓编码分析形态特征与外观意象的关联，将结果用于两组方案比较及后续外观迭代。

Research Focus / 研究对象与问题
如何描述用户的外观感知？

用6组语义词对评价整车外观，分析主要感知维度。

感知判断如何用于造型决策？

分析语义评分与构件轮廓的关联，为构件选择和方案比较提供依据。

Study Data / 研究数据
8款车型样本

选取不同品牌、具有典型造型特征的车型，组成外观评价样本集。

101份有效问卷

围绕6组核心语义词对完成评价，Cronbach's α > 0.8。

3类构件 · 10项变量

对前大灯、引擎盖与进气格栅提取轮廓，并进行形态特征编码。

KMO 0.753

采用因子分析提炼感知维度，Bartlett球形度检验 p < 0.01。

Research Design / 研究设计
样本与品牌筛选视觉关注区识别语义差异评价信效度检验因子分析形态特征编码形态与意象映射方案迭代
Research Documentation / 研究过程与材料
Key Findings / 主要研究发现
重点构件识别

眼动分析显示，用户的视觉关注主要集中在前大灯、引擎盖与进气格栅，据此选取轮廓编码对象。

感知维度提取

因子分析将外观感知评价归纳为造型风格、体量简约与色彩装饰三个维度。

形态与意象关联

依据轮廓类别与语义评分的关联选择构件形态，再结合品牌特征调整整车比例和视觉重心。

Design Application / 设计应用
感知目标形态变量造型处理
可靠感前脸宽高比例、横向秩序强化横向布局与对称关系，营造稳定的视觉感受。
力量感机罩体量、下部视觉支撑加强机罩整体性，降低视觉重心，表达稳重感。
亲和度灯具表情、轮廓曲率减少尖锐折线，尝试形成较温和的前脸表情。
品牌识别家族化前脸、色彩关系延续品牌识别特征，形成系列化外观语言。

表中列出的是方案的造型目标与处理方式；量化评价采用原研究的6组语义词对。

Project 02 / Service Study

面向二手家具循环流通的用户端服务系统设计

面向二手家具循环流通的用户需求研究与服务系统设计

SIVA需求提取Kano分类AHP权重PSS构建SUS评价

本项目研究二手家具再次流通时的用户决策，关注家具状态、估值依据、交易信任、物流履约与售后责任等问题。在此基础上，设计检测估值、交易匹配、物流履约、售后追踪和循环价值展示等服务流程及用户端原型。

Research Process / 研究过程
  1. 问题界定识别二手家具流通中的交易信任、估值、履约与循环价值问题。
  2. 需求分析以SIVA梳理需求，经Kano分类、Better-Worse分析和AHP确定优先级。
  3. 系统构建梳理平台与检测、翻新、物流、售后服务之间的分工和衔接。
  4. 原型评价依据服务蓝图形成用户端原型，再以SUS量表评价可用性。
Summary / 项目摘要

通过调研形成需求清单，经Kano分类与AHP排序后设计服务系统和用户端原型，再采用SUS量表评价原型的可用性。

Research Focus / 研究对象与问题
哪些信息支持交易判断？

在界面中说明家具状态、来源、估值依据与售后责任，供用户核查。

需求如何转为服务功能？

将用户对信任、价格、交付与循环价值的需求转为具体功能和服务流程。

线上线下如何衔接？

梳理平台、检测、翻新、仓储物流与售后服务的分工及交接流程。

Study Data / 研究数据
96份有效问卷

每份评价26项需求，共2,496组Kano正反向配对判断；总体α=0.925，KMO=0.880。

26项用户需求

解决方案7项、信息8项、价值6项、可及性5项，按SIVA四个维度组织。

10位专家

对筛选保留的20项需求开展AHP评价，确定需求权重与功能优先级。

37名参与者

每人完成10题SUS量表，平均得分82.86/100；按原研究采用的分级标准为A级。

Research Design / 研究设计
探索性预调研SIVA需求提取Kano需求分类Better-Worse分析AHP权重排序PSS关系构建服务蓝图与原型SUS评价
Research Documentation / 研究过程与材料
Key Findings / 主要研究发现
需求优先级

满足使用要求与价格经济性的综合权重居前，其次为购买和回收服务，据此安排功能优先级。

服务系统结构

方案将估值检测、质量评价、回收翻新、预约配送和订单追踪纳入同一服务流程。

原型评价

本次SUS评价针对用户端原型的可用性；实际交易表现、信任变化与资源节约效果仍需后续研究。

Design Application / 设计应用
用户问题设计方向功能与信息
家具状态不透明呈现检测结果与成色分级损伤标注、修复记录与质量说明。
价格依据不足说明估值依据在线预估值、成色说明与价格信息。
履约过程割裂衔接交易与交付流程预约、物流、交付与售后状态追踪。
循环价值不易理解展示家具再利用的信息环保标签、循环记录与价值可视化。

Project 03 / System Study

面向检查检验互认的跨院诊断报告共享系统设计

面向检查检验互认的跨院报告共享与授权机制研究

政策与标准梳理多主体需求QFD功能规划信息架构任务评价

本项目围绕跨院复诊、转诊接续和慢病随访，分析报告来源核验、患者授权、互认状态及访问记录等需求。通过梳理患者、医生、医疗机构和平台的任务分工与权限关系，设计系统架构与患者端原型。

Research Process / 研究过程
  1. 对象界定以跨院复诊、转诊接续和慢病随访为主要使用场景。
  2. 功能规划结合政策标准与各方需求，通过QFD分析确定功能优先级。
  3. 系统构建围绕来源核验、患者授权、统一索引与访问追踪设计功能。
  4. 原型评价通过小样本任务测试与专家走查，识别交互问题并提出修改方向。
Summary / 项目摘要

从跨院报告共享任务中提取信息与授权需求，经QFD分析确定功能优先级，设计患者端原型，再通过任务测试和专家走查提出交互改进方向。

Research Focus / 研究对象与问题
患者侧

如何了解报告来源、授权范围、互认状态与访问记录？

医生侧

如何查看报告来源、完整性及可供诊疗参考的信息？

系统侧

如何协调患者、医生、医疗机构与平台之间的权限和任务关系？

Study Data / 研究数据
15项候选需求

涵盖报告检索、来源核验、授权管理与连续追踪等需求，作为QFD分析的输入。

5类功能方向

统一索引、可信核验、动态授权、互认辅助与连续追踪。

5项关键任务

报告查找、共享授权、可信核验、使用追踪与趋势查看。

五项任务平均完成率88.9%

平均完成时间49秒，平均易用性评分4.08/5，用于评价患者端原型并确定改进方向。

Research Design / 研究设计
政策与标准梳理多主体角色识别核心场景聚类任务链拆解QFD功能规划信息架构设计高保真原型任务测试与走查
Research Documentation / 研究过程与材料
Design Highlights / 设计要点
信息核验

在跨院调阅流程中呈现报告来源、时间、完整性与核验标识，支持用户核查。

授权管理

在同一流程中呈现授权对象、范围、时效及使用记录，并提供撤回入口。

跨院使用

通过统一索引、结构化摘要与访问追踪，衔接跨机构的报告查找、阅读和后续使用。

Design Application / 设计应用
使用问题设计方向功能与信息
报告来源难以核查呈现来源核验信息机构、时间、完整性与核验标识。
授权边界不清提供动态授权控制对象、范围、时效、撤回与到期提醒。
重点信息难读取组织结构化摘要异常项提示、历史对比与关键信息提取。
跨院使用难追溯设计访问与使用记录查看记录、共享路径与访问日志。
Research Output / 研究产出

患者端跨院报告共享原型。覆盖报告检索、来源核验、动态授权、状态提示与访问追踪。

原型任务测试与专家走查。评价范围为患者端的信息理解与操作流程，后续可在真实医疗环境中检验跨院协作与持续使用情况。
